# AI 安全规范（实验四）

本项目的安全基线，尤其是「用户可控输入 → 模型」链路的防护要求。

## 一、密钥与密码管理

- **密码入库必须加密**：本项目使用 BCrypt（`SecurityConfig.passwordEncoder()`），`DataInitializer` 中所有演示账号密码均经 `passwordEncoder.encode()` 后入库，数据库中绝不存明文。
- **密钥绝不硬编码/入库**：JWT 签名密钥放在配置 `application.yml` 的 `jwt.secret`，生产环境须改用环境变量或密钥管理服务注入，并保证长度 ≥ 32 字节（HS256 要求）。
- **日志不打印敏感信息**：禁止在日志中输出密码、token、密钥。

## 二、令牌（Token）安全

- JWT 通过 `Authorization: Bearer <token>` 传递，后端每次请求校验签名与过期时间。
- **前端不裸存明文令牌**：不要长期明文存 localStorage 中重要的持久化凭据；生产环境建议使用 httpOnly Cookie 或短期内存存储，降低 XSS 泄露风险（本项目前端为演示，使用 localStorage，见 `request.js` 注释）。
- 后端对未登录（401）与无权限（403）返回统一 JSON，前端据此跳转登录。

## 三、提示注入（Prompt Injection）防护

凡是将「用户可控输入」拼接到 AI/LLM 提示词的场景，均需防护：

1. **输入视为不可信数据，而非指令**：把用户输入作为 `data` 字段、用明确分隔符包裹，禁止直接拼接进系统提示词。
2. **输入校验**：对长度、字符集、格式做白名单校验后再使用（参考 `AuthController.login` 的输入校验）。
3. **输出校验**：对模型输出做二次校验/过滤，避免把模型生成的恶意内容直接执行或渲染（防存储型 XSS）。
4. **最小权限**：模型/接口只授予完成任务所需的最小权限，限制其可触达的数据范围。

## 四、接口权限（RBAC）

- 后端通过 `@PreAuthorize` 做方法级权限控制，权限由「用户-角色-权限」三表 + 关联表维护。
- 演示账号与权限：

| 账号 | 密码 | 角色 | 权限 |
|---|---|---|---|
| admin | admin123 | ADMIN | 查看/新增/修改/删除员工、查看部门 |
| hr | hr123 | HR | 查看/新增/修改员工、查看部门 |
| user | user123 | EMPLOYEE | 查看员工、查看部门 |

> 前端隐藏按钮仅改善体验，**真正的安全边界在后端**，任何接口都不得仅靠前端隐藏来保护。
